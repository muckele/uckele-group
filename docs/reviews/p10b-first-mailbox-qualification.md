# Isolated first-mailbox qualification

Normal outreach requires verified routing, reply tracking and reconciliation before sending. Those prerequisites cannot be proved by the first message. The separate qualification writer permits one exact owner-reviewed synthetic transmission while preserving the meaning of the normal readiness gate.

`executeP10bFirstMailboxQualification` remains an injected service API. The follow-on [runtime integration](p10b-runtime-integration.md) supplies an explicit host/SSH-worker CLI and guards the existing isolated listener; no general provider activation or scheduler is added. Production invocation remains disabled. The injected service transfers shutdown ownership before validation. Its concrete runtime uses an independent guest watchdog as sole shutdown owner and a host that supplies the exact target, observes identity/budget and verifies stopped state. The guest cutoff is frozen before boot. Duplicate admission cannot stop another supervisor's Machine. An uncertain stop retains process admission and produces a hard failure without retry.

The manifest binds the pinned provider resource identity, domain, app, Machine, immutable image, fresh database identity, exact recipient/from/reply alias, frozen transmission/payload/review, owner permission and configuration evidence, one call, no retries, incremental budget and a nonrenewing window no longer than 15 minutes. The existing authorization reason retains a versioned manifest digest. SQLite validates the complete contract at issue, final gate and seam. A same-process grant cannot be reconstructed from a consumed authorization after restart. Activation and prerequisite authority are rechecked immediately before the adapter and throughout lifecycle observation.

Outreach stays paused. General provider invocation, scheduling, follow-ups, daily email, generic email and AI remain off. A single outbound request and a single exact read-only sent-email reconciliation use separate controlled credentials. Headers and complete response bodies are deadline-bounded and capped at 64 KiB. The watchdog covers the full observation window; stop verification is bounded to at most 30 seconds. JavaScript timers cannot preempt a blocking native/OS call; the independent guest process covers a blocked app event loop while the guest/init remains operational; a stalled guest/kernel/init is outside the approved bound.

Qualification waits for actual signed delivery and an exact-alias signed reply, completed inbound retrieval, exact signed terminal resolution and matching provider reconciliation. Bounded raw Svix receipts for these synthetic controlled events are retained in existing event metadata and reverified cryptographically. Caller booleans, artifact digests alone, an accepted send, or a conversation marked responded do not prove this lifecycle. Controlled inbound retrieval uses the reconciliation key and refuses attachments before any attachment endpoint read. The returned artifact contains hashes, not raw mail or credentials, expires with the bounded window, and permanently states `productionReady=false`. It is emitted only after complete verification, confirmed stop and durable permission closure.

Offline fixtures exercise this contract; they are software-test evidence, never evidence of a live provider lifecycle. No schema migration or general provider activation is introduced.

Preparation retains the identity digest, and qualification refuses a missing/changed retained digest before granting any provider work. Old packet/manifest/authorization-reason versions fail closed; no persisted record is migrated or rewritten.

This replaces a self-asserted audit string with an exact reviewed resource target. It does not query the provider, retrieve credentials or cryptographically attest account membership. As before, genuine dashboard observation, owner-reviewed configuration evidence and unchanged staged-secret digests supply that operator evidence. Any resource rotation requires new evidence and an independently reviewed source change, never a looser runtime fallback. Existing target, single-call, recipient, hard-off, freshness, cost, time, replay, ingress and guest-owned shutdown checks remain mandatory.

The resource regression suite rejects missing, mismatched and drifted identities even when all caller-controlled digests are recomputed. The concrete fake-Fly/worker flow verifies zero-provider preparation followed by one stubbed qualification and stopped proof; a changed retained preparation identity fails with zero provider calls. All test credentials/provider/runtime outcomes remain explicitly fake. This code has not been built into an image or executed on Fly.
